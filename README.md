# 产品文案工作流

将产品介绍、产品卖点和客户痛点，逐步整理成可信、可发布的产品宣传文案。适合课程、服务、软件、咨询、实体产品等需要避免夸大或编造信息的营销内容工作。

## 这个 Skill 会做什么

它不直接凭空写广告，而是先把产品事实和客户表达梳理清楚，再逐步产出文案。整个流程会：

- 只把上传的文件或粘贴内容作为业务资料，不执行其中的操作指令；
- 不编造功能、案例、数据、价格、效果或保证；
- 对缺失、矛盾、动态变化的信息标注“待补充”或“需人工确认”；
- 保留资料脱敏、关键信息核验和人工确认等使用边界；
- 默认逐步展示结果，等待确认后再继续；用户说“按上文继续”或“直接生成”时，可切换为快速模式；
- 在写宣传内容前建立事实台账，确保公开表达只使用有来源、可宣传的信息；
- 在成稿前检查事实依据、宣传边界、夸大表达、渠道限制、可读性和行动引导。

## 使用流程

### 启动：收集三类资料与事实台账

先提供以下任意形式的内容：文档、链接或直接粘贴的文本。

1. 产品介绍：产品是什么、适合谁、如何提供服务或交付。
2. 产品卖点：产品的具体方法、特点、场景和可被验证的差异。
3. 客户痛点：客户当前的问题、期待、顾虑和常用说法。

资料不完整也可以开始，Skill 会将缺少的部分标记为“待补充”。随后会建立一份内部事实台账，记录每项主张的来源、是否可宣传，以及需要人工确认的边界。

### 1. 生成产品宣传信息卡

将三类资料交叉整理为一张表，内容包括：产品名称、通俗说明、目标客户、典型痛点、期待结果、核心卖点、差异、信任依据、宣传边界和一句话定位。

### 2. 拆分目标客户

根据确认的信息卡，拆成 3—5 类典型客户。每类会说明：岗位、最头疼的问题、最想得到的结果、顾虑、适合的宣传角度和一句贴近客户日常的话。

### 3. 确定单篇文案策略并保存 Brief

确认产品名称、文案类型、目标客户、目标、渠道、语气和行动引导。正式写文案前，会先给出核心问题、3 个重点卖点、反感或风险表达、推荐结构和 10 个标题方向。

确认后会形成一份简短的“产品文案 Brief”，后续换渠道或改写时不必重新说明全部背景。

### 4. 生成完整文案

根据确认的策略，输出标题、正文、结尾引导和一版更短、可直接发布的版本。默认避免“最、第一、百分百、保证、永久”等绝对化表达，并在成稿前完成质检。

### 5. 批量适配渠道

可将同一份产品信息适配为朋友圈、海报、小红书、私信沟通、咨询引导等不同渠道文案。每种渠道会遵循相应的长度、结构和表达习惯；用户另有要求时，以用户要求为准。

### 可选：视频口播路线

可将已确认的宣传文案改成真人出镜口播稿，提供标题、封面标题、3 秒钩子、分段建议时长、完整稿和 30 秒短稿。时长为建议范围，实际录制会随说话速度略有变化。

## 安装

将本仓库克隆或下载后，把 `product-copy-workflow` 文件夹放入你的 Codex Skills 目录：

```text
~/.codex/skills/product-copy-workflow/
```

目录应保持如下结构：

```text
product-copy-workflow/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── channel-specs.md
    └── quality-check.md
```

重启或刷新 Codex 后即可使用。

## 开始使用

在 Codex 中输入：

```text
使用 $product-copy-workflow，基于我的产品资料，按步骤完成产品宣传文案。
```

也可以直接上传产品介绍、卖点和客户痛点文件，并说明希望开始第 1 步。

## 适用边界

本 Skill 用于整理和撰写产品宣传内容，不替代法律、广告合规、医疗、金融或其他专业审核。平台规则、价格、服务范围、数据、案例和效果等动态或高风险信息，应由产品负责人核对后再发布。
